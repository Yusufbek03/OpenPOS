# 1. Purpose

Kitchen Display System (KDS) — это приложение для кухни, которое принимает заказы от POS в реальном времени.

KDS заменяет бумажные чеки и помогает поварам отслеживать процесс приготовления.

---

# 2. Goals

Основные задачи:

- отображение новых заказов;
- автоматическое обновление;
- автопечать кухонных чеков;
- контроль времени приготовления;
- изменение статусов;
- уведомление кассира о готовности.

---

# 4. Order Card

Каждая карточка должна отображать:

- номер заказа;
- номер стола (если ресторан);
- имя официанта;
- время создания;
- время ожидания;
- список блюд;
- комментарии;
- статус;
- приоритет.

---

# 5. Order Status

Поддерживаются статусы:

```
NEW

ACCEPTED

PREPARING

READY

SERVED

CANCELLED
```

---

🔴 Red

---

# 7. Auto Refresh

После создания заказа:

POS

↓

Backend

↓

WebSocket

↓

Kitchen Display

Никакого обновления страницы.

---

# 8. Auto Print

После получения нового заказа:

Backend

↓

Printer Service

↓

Kitchen Printer

↓

Чек печатается автоматически.

---

# 9. Sound Notification

Каждый новый заказ сопровождается:

- звуковым сигналом;
- анимацией карточки;
- счетчиком новых заказов.

---

# 10. Sorting

Карточки можно сортировать:

- по времени;
- по приоритету;
- по номеру заказа;
- по статусу.

---

# 11. Filtering

Фильтр по:

- станции;
- статусу;
- официанту;
- столу.

---

# 12. Kitchen Stations

Поддерживаются станции:

```
Kitchen

Bar

Dessert

Bakery

Grill
```

Каждая станция получает только свои блюда.

---

# 13. Station Routing

Пример:

```
Burger

↓

Kitchen

Coffee

↓

Bar

Cake

↓

Dessert
```

---

# 14. Timer

Каждый заказ имеет таймер.

Пример:

```
02:35
```

Если превышено нормативное время:

карточка становится красной.

---

# 15. Bulk Actions

Можно:

- принять все;
- отметить готовыми несколько заказов;
- отменить заказ;
- повторно распечатать чек.

---

# 16. Kitchen Notes

Комментарии отображаются крупным шрифтом.

Например:

```
Без лука

Очень остро

Без сахара

Упаковать отдельно
```

---

# 17. Ready Notification

После изменения статуса на READY

↓

Backend

↓

WebSocket

↓

POS

↓

Официант получает уведомление.

---

# 18. Offline Mode

Если интернет пропал:

- текущие заказы доступны;
- новые локальные изменения сохраняются;
- после восстановления связи выполняется синхронизация.

---

# 19. Performance

Появление нового заказа

< 500 мс

Изменение статуса

< 200 мс

---

# 20. Security

Только сотрудники кухни имеют доступ к KDS.

Все действия записываются в Audit Log.

---

# 21. Error Handling

Если принтер недоступен:

- показать предупреждение;
- сохранить чек в очереди;
- автоматически повторить печать.

---

# 22. WebSocket Events

Получение заказа:

```
order.created
```

Изменение статуса:

```
order.updated
```

Готовность:

```
order.ready
```

Отмена:

```
order.cancelled
```

---

# 23. Acceptance Criteria

Модуль считается готовым, если:

✅ Новый заказ появляется автоматически.

✅ Работает таймер.

✅ Работает изменение статуса.

✅ Работает автопечать.

✅ Работает маршрутизация по станциям.

✅ Работают уведомления.
