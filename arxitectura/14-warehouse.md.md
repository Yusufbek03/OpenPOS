
# OpenPOS Warehouse Management System (WMS)

**Document:** 14-warehouse.md

**Project:** OpenPOS

**Version:** 1.0

**Status:** Approved

---

# 1. Purpose

Warehouse Management System (WMS) отвечает за полный учет товарных запасов.

Модуль должен автоматически обновлять остатки после каждой продажи, возврата, прихода или списания.

Поддерживается работа с одним или несколькими складами.

---

# 2. Goals

Основные задачи:

- учет остатков;
- приход товара;
- списание;
- перемещение между складами;
- инвентаризация;
- контроль минимального остатка;
- история движения товара.

---

```
Warehouse

├── Suppliers
├── Purchase Orders

```

---

# 4. Warehouse Structure

Поддерживается:

- один склад;
- несколько складов;
- зоны хранения (Future);
- полки (Future).

---

# 5. Stock Card

Для каждого товара отображаются:

- SKU;
- штрихкод;
- название;
- категория;
- текущий остаток;
- минимальный остаток;
- максимальный остаток;
- себестоимость;
- цена продажи;
- поставщик.

---

# 6. Goods Receipt

Приход товара включает:

- поставщика;
- номер документа;
- дату;
- список товаров;
- количество;
- закупочную цену.

После подтверждения:

остатки увеличиваются автоматически.

---

# 7. Write Off

Причины списания:

- порча;
- просрочен;
- потеря;
- внутреннее использование;
- производство.

Все списания логируются.

---

# 8. Stock Transfer

Перемещение товара между складами.

```
Main Warehouse

↓

Coffee Shop

↓

Kitchen
```

Каждое перемещение имеет статус:

```
Draft

In Transit

Completed

Cancelled
```

---

# 9. Inventory Count

Инвентаризация позволяет:

- пересчитать остатки;
- выявить расхождения;
- автоматически сформировать корректировки.

---

# 10. Minimum Stock

Для каждого товара задается минимальный остаток.

При достижении лимита система создает уведомление.

Например:

```
Coffee Beans

Осталось:

2 кг

Минимум:

5 кг
```

---

# 11. Suppliers

Для каждого поставщика хранится:

- название;
- ИНН;
- телефон;
- Email;
- адрес;
- контактное лицо.

---

# 12. Purchase Orders

Поддерживаются:

- создание заказа поставщику;
- редактирование;
- отправка;
- получение товара;
- закрытие заказа.

---

# 13. Stock History

Каждое изменение остатка записывается.

Причины:

- продажа;
- возврат;
- приход;
- списание;
- инвентаризация;
- перемещение.

---

# 14. Product Cost

Хранится:

- закупочная цена;
- средняя цена;
- последняя закупочная цена.

В будущем:

FIFO

LIFO

Weighted Average

---

# 15. Barcode Support

Поддерживается:

- поиск по штрихкоду;
- прием товара сканером;
- инвентаризация сканером.

---

- остатки;

# 22. Security

Все операции требуют авторизации.

Все изменения записываются в Audit Log.

Удаление документов запрещено.

Разрешена только отмена с сохранением истории.

---

Модуль считается завершенным если:

✅ Работает приход.

✅ Работает списание.

✅ Работает перемещение.

✅ Работает инвентаризация.

✅ Работают отчеты.

✅ Работает история движения.
