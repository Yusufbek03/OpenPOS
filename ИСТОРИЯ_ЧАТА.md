# История разработки OpenPOS

## Стек
- Frontend: React + TypeScript + Vite + Zustand + TanStack Query
- Backend: Vercel Serverless Functions (12 functions max)
- База данных: Supabase (PostgreSQL)
- Auth: Supabase Auth + JWT (пароль/OTP/Google OAuth)
- Хранилище: Supabase Storage (фото)
- Деплой: Vercel + GitHub
- Домен: https://openpos-terminal.vercel.app
- Supabase: https://ytanvpjxqfdxcvghmzny.supabase.co

## Исправления и фичи по датам

### 2026-07-31

#### 1. PIN-код — эндпоинт set-pin отсутствовал
- **Проблема**: `POST /auth/set-pin` возвращал 404 — эндпоинт не был создан
- **Исправление**: Добавлен обработчик `set-pin` в `api/auth/[...slug].ts`
- **Файлы**: `api/auth/[...slug].ts`

#### 2. Google OAuth в PWA не работает
- **Проблема**: В установленном PWA Google OAuth открывает браузер, не возвращаясь в приложение
- **Исправление**: В standalone-режиме кнопка Google скрыта, используются только пароль/OTP
- **Файлы**: `apps/pos/src/pages/login.tsx`

#### 3. Баг слагов — PATCH/DELETE не работали
- **Проблема**: `req.query['...slug']` в Vercel возвращает строку, не массив. `slug[0]` брал первый символ UUID
- **Исправление**: Парсинг `Array.isArray(raw) ? raw : raw.split('/')` во всех 4 файлах
- **Файлы**: `api/categories/[...slug].ts`, `api/products/[...slug].ts`, `api/orders/[...slug].ts`, `api/users/[...slug].ts`

#### 4. Формат ответа products
- **Проблема**: API возвращает `{ items: [...] }`, а фронтенд читал `data.products`
- **Исправление**: `data.items || data.products || data` во всех местах
- **Файлы**: `apps/pos/src/pages/admin/admin-products.tsx`, `apps/pos/src/hooks/use-pos-data.ts`, `apps/pos/src/pages/admin/admin-inventory.tsx`

#### 5. Supabase Storage — загрузка фото
- **Проблема**: Bucket `uploads` не существовал, RLS блокировал загрузку
- **Исправление**: Создан bucket в Supabase Dashboard + SQL policy для доступа
- **SQL**: `CREATE POLICY "Allow all for uploads bucket" ON storage.objects FOR ALL USING (bucket_id = 'uploads') WITH CHECK (bucket_id = 'uploads');`

#### 6. Фото возвращали неправильный URL
- **Проблема**: Upload handler возвращал относительный путь `/uploads/filename`, а нужен полный Supabase URL
- **Исправление**: `supabase.storage.from('uploads').getPublicUrl(filePath)` + фронтенд использует полные URL
- **Файлы**: `api/uploads/image.ts`, `apps/pos/src/pages/admin/admin-categories.tsx`, `apps/pos/src/pages/admin/admin-products.tsx`, `apps/pos/src/pages/pos-page.tsx`, `apps/pos/src/components/pos/product-grid.tsx`

#### 7. Triple-tap логотип → админка
- **Фича**: 3 быстрых клика на «OP OpenPOS» → открывается вход в админку
- **Файлы**: `apps/pos/src/components/pos/top-bar.tsx`, `apps/pos/src/pages/pos-page.tsx`

#### 8. Оплата 404 — эндпоинт payments отсутствовал
- **Проблема**: `POST /payments` не существовал, оплата падала с 404
- **Исправление**: Добавлен обработчик payments в `admin-handler.ts` + перенаправление из фронтенда
- **Файлы**: `api/admin-handler.ts`, `apps/pos/src/lib/api.ts`

#### 9. Печать чека — broken printer API
- **Проблема**: `GET /printers` и `POST /printers/print-receipt` не существовали
- **Исправление**: Печать через скрытый iframe + браузерный print dialog
- **Файлы**: `apps/pos/src/components/pos/payment-modal.tsx`

#### 10. Печать — ошибка из-за timing
- **Проблема**: `tryPrintReceipt` вызывался до отрисовки чека в DOM (`receiptRef.current` = null)
- **Исправление**: Добавлен `setTimeout(() => tryPrintReceipt(order.id), 600)` для ожидания рендера
- **Файлы**: `apps/pos/src/components/pos/payment-modal.tsx`

#### 11. Фото категорий/товаров не сохранялись
- **Проблема**: Stale closure в `onCropped` — `setForm({ ...form, imageUrl })` использовал устаревший `form`
- **Исправление**: Functional update `setForm((prev) => ({ ...prev, imageUrl: data.url }))`
- **Файлы**: `apps/pos/src/pages/admin/admin-categories.tsx`, `apps/pos/src/pages/admin/admin-products.tsx`

#### 12. Фото в карточках категорий
- **Исправление**: Карточки категорий показывают фото если загружено, иначе иконку
- **Файлы**: `apps/pos/src/pages/admin/admin-categories.tsx`

#### 13. Заказы — branchId не найден
- **Проблема**: Кассир без branchId не мог создавать заказы (FK constraint)
- **Исправление**: branchId fallback на существующий филиал `c0000001-0000-0000-0000-000000000001`
- **Файлы**: `api/orders/index.ts`

## Архитектура API (Vercel Serverless Functions)

### 12 функций (Hobby лимит)
1. `api/auth/[...slug].ts` — login, refresh, logout, me, verify-pin, set-pin, users-for-pin, supabase-login
2. `api/categories/index.ts` — GET list, POST create
3. `api/categories/[...slug].ts` — GET/:id, PATCH/:id, DELETE/:id
4. `api/products/index.ts` — GET list, POST create
5. `api/products/[...slug].ts` — GET/:id, PATCH/:id, DELETE/:id
6. `api/orders/index.ts` — GET list, POST create
7. `api/orders/[...slug].ts` — GET/:id, PATCH/:id, DELETE/:id, send-to-kitchen, return
8. `api/users/index.ts` — GET list, POST create
9. `api/users/[...slug].ts` — GET/:id, PATCH/:id, DELETE/:id
10. `api/uploads/image.ts` — загрузка фото в Supabase Storage
11. `api/admin-handler.ts` — flat handler: customers, suppliers, printers, kitchen, tables, register-ops, audit, dashboard, inventory, companies, users, payments, reports/daily, reports/profit
12. `api/kitchen-handler.ts` — kitchen stations, tickets

### Дополнительные API (не в лимите 12 — разные entry points)
- `api/shifts.ts` — смены: open, close, current, x-report, list
- `api/reports.ts` — отчёты: daily, period, profit

### Ключевые архитектурные решения
- **`api-shared/supabase.ts`** — вынесен за пределы `api/` чтобы не считаться как функция
- **Клиентский интерсептор** в `api.ts` — трансформирует `/admin/*` → `/admin-handler?_path=*` и `/kitchen/*` → `/kitchen-handler?_path=*`
- **`/payments`** → перенаправляется в `admin-handler?_path=payments`

## 2026-08-04

### 14. Оптимизация производительности — главный бандл 522KB → 259KB
- **Проблема**: Главный JS бандл был 522KB (151KB gzip) — слишком медленная загрузка
- **Причины**: Мёртвые зависимости (@openpos/config, @openpos/shared, @openpos/ui) попадали в клиентский бандл
- **Исправление**:
  - Удалены `@openpos/config` и `@openpos/shared` из package.json (не использовались в POS)
  - `cn()` из `@openpos/ui` инлайнится в `apps/pos/src/lib/cn.ts`
  - Vite `manualChunks` — react-query, supabase, lucide, socket.io вынесены в отдельные чанки
  - Kitchen polling отключается когда WebSocket подключён
- **Результат**:
  | Что | Было | Стало |
  |-----|------|-------|
  | index.js | 522KB (151KB gzip) | 259KB (82KB gzip) |
  | vendor-supabase | — | 215KB (отдельный чанк) |
  | vendor-query | — | 50KB (отдельный чанк) |
  | vendor-socket | — | 41KB (отдельный чанк) |
  | vendor-icons | — | 29KB (отдельный чанк) |
  | kitchen-page | 52KB | 8.8KB |
- **Файлы**: `apps/pos/package.json`, `apps/pos/vite.config.ts`, `apps/pos/src/lib/cn.ts`, `apps/pos/src/pages/kitchen-page.tsx`

### 15. Фото категорий — прямая загрузка вместо ImageCropper
- **Проблема**: ImageCropper в categories конфликтовал с модальным окном формы (два `position: fixed` слоя z-index 50 и 100)
- **Исправление**: Заменён на прямую загрузку файла через hidden input + useRef + fetch upload
- **Файлы**: `apps/pos/src/pages/admin/admin-categories.tsx`

### 16. Управление сменами (Shift Management)
- **Проблема**: Нет модели смен — невозможно отслеживать открытие/закрытие кассы, баланс, X/Z отчёты
- **Реализация**:
  - SQL миграция: таблица `shifts` (id, branchId, cashierId, status, openingBalance, closingBalance, cashCount, totalSales, totalCash, totalCard, totalOther, totalOrders, openedAt, closedAt, notes)
  - API: `POST /api/shifts?action=open` — открытие смены с начальным балансом
  - API: `POST /api/shifts?action=close` — закрытие смены с подсчётом наличных
  - API: `GET /api/shifts?action=current` — текущая открытая смена
  - API: `GET /api/shifts?action=x-report&shiftId=` — X-отчёт за смену
  - API: `GET /api/shifts?action=list` — список смен с фильтрацией
  - Frontend: `shift-store.ts` — Zustand store с localStorage persist
  - Frontend: `open-shift-modal.tsx` — модалка открытия с начальным балансом
  - Frontend: `close-shift-modal.tsx` — модалка закрытия с X-отчётом и печатью
  - Top bar: кнопка «Открыть смену» / индикатор «Смена открыта · HH:MM»
- **SQL**: `migrations/001_shifts.sql`
- **Файлы**: `api/shifts.ts`, `apps/pos/src/stores/shift-store.ts`, `apps/pos/src/components/pos/open-shift-modal.tsx`, `apps/pos/src/components/pos/close-shift-modal.tsx`, `apps/pos/src/components/pos/top-bar.tsx`

### 17. Отчёты — продажи и прибыль
- **Проблема**: Есть только базовый дашборд, нет отчётов по продажам/прибыли с фильтрацией по датам
- **Реализация**:
  - API: `GET /admin/reports/daily?from=&to=` — дневной отчёт (продажи, заказы, позиции, средний чек, оплата по методам)
  - API: `GET /admin/reports/profit?from=&to=` — отчёт по прибыли (выручка, себестоимость, маржа, топ товары по прибыли)
  - Frontend: `admin-reports.tsx` — страница отчётов с табами «Продажи» / «Прибыль»
  - Фильтр по датам (from/to), прогресс-бар для методов оплаты, таблица товаров по прибыли
- **Файлы**: `api/admin-handler.ts` (handleDailyReport, handleProfitReport), `api/reports.ts`, `apps/pos/src/pages/admin/admin-reports.tsx`, `apps/pos/src/pages/admin/admin-panel.tsx`

### 18. CORS — добавлен *.vercel.app
- **Проблема**: CORS allowed origins содержал только конкретный домен
- **Исправление**: Добавлен wildcard `https://*.vercel.app` для preview деплоев
- **Файлы**: `api-shared/supabase.ts`
